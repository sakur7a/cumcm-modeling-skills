# 算法实现、迭代优化与统计

## 可复现基线

先保存能运行的基线及配置。记录源码哈希、数据指纹、种子、环境、依赖、误差模式、参数和评估口径。原始输出不可覆盖；源码、配置或模型改变使用新运行目录，不修改旧指纹伪造恢复。生产、候选实验、最终冻结入口明确分开。

实现模型不变量、边界检查、预算和完成条件。优化排序、路径、缓存或共享动作时，检查对计数、状态、观测来源及后续决策的影响。推导结果不能冒充实际测量，节省动作不能悄悄改变用于证明的历史。

测试聚焦行为变化和已发现漏洞：边界、退化、空集合、模型矛盾、未知响应、额度耗尽、兜底及安全终止。文档修改不重跑大批量算法；代码通过适当测试后，仅因新失败或疑点扩大测试。

## 固定案例与独立确认

用户需要持续比较时建立规模适合预算的固定开发集；500–1000例可作为起点，不是所有题目必需规模。固定完整物理场景和噪声机制，不仅固定编号。覆盖自然分布、困难边界及不同模型解释，验证文件指纹。

区分训练/筛选集、未见确认集、压力集。反复查看和调参后的固定集是开发回归集，不能继续称独立验证。候选先筛选、再确认，失败保留全分母。若不断依据确认集调参，要换新的独立集或诚实标为开发证据。

同案例比较新旧策略；随机性相同且合理时配对。按整案例同时抽取新旧记录估计区间，说明统计方法和样本单位。报告均值、中位数、P95、最坏值、失败/超时率、获胜比例及重要分层。尾部风险和相对旧策略退化、绝对耗时长尾、漏解/超时分别解释。

## 统计口径

- 清除比例 = 已清除数 / 真实源总数；真实总数未知时该比例缺失，不能用发现数代替。
- 单局平均定位清除时间 = 对应定位清除总时间 / 已清除数；零清除时平均未定义，保留失败与总时间。
- 合并平均时间 = 各局总时间之和 / 各局清除数之和；不同于逐局平均时间的算术平均。标签写明使用哪一种。
- 时间至少区分算法 CPU/计算时间、客户端墙钟、协议时间戳差、模拟器虚拟动作时间。起止点、倒计时/数据准备是否包含、分辨率、网络影响都要注明。
- UI 缺字段先检查协议或已有客户端证据；可报告有明确来源的派生计时，不能伪装成 UI 官方公布值，也不机械认定没计时。
- 完成率分母按请求、实际开始、实际进入分别统计。未启动、已启动未进入、部分完成、未知、导出失败均保留，不能只筛全清局。

## 证据权重与取舍

合成环境检验模型与回归，HTTP 替身检验协议实现，官方演练检验真实系统，正式测试提供有限最终成绩。即使核对主要规则，本地模型也可能不知官方分布、量化和误差场，不能称完全等价。记录一致与未知项；未知会影响结论时提高官方演练权重。

官方随机案例不能称同案例配对提速。允许比较时预先安排候选分组、保留全部结局、报告不确定性；不要把本地提升百分比移植为官方提升。正式测试不用作反复筛选。

每轮提出可证伪机制、最小改动、对照、鲁棒性门槛和预算。停止条件可以是收益不稳定、风险增加、预算结束或用户停止；保存未采纳候选与原因。未经证据支撑不承诺提速50%或逐例占优。
