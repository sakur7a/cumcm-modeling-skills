# Prompt 调用示例

以下按作者提供的实际提示整理，保留自然对话方式，仅将队号与材料路径改为通用占位符。在安装技能后的首次消息中可加 `使用 $cumcm-modeling`，后续直接说当前想做的事，不需要每轮重复技能全文。

## 1. 初始化项目

```text
使用 $cumcm-modeling。
初始化一个git，每次对话后更新。
参赛队号为：<参赛队号>，不要在代码中硬编码，后续正式提交时需要匿名。
你维护一个工作文档，以题目为标题。
记录具体题目的要求，比如模拟器需要如何启动和接入。
维护一个AGENTS文档管理核心的规则。
```

队号是示例字段，实际运行按私有配置提供；匿名要求是本次任务约定，不是Git匿名提交要求。模拟器要求按题目具体填写，无模拟器时省略。

## 2. 专注前两问的理论

```text
现在专注问题1和问题2，关注其数学建模部分。
数学建模是否已经是最优了？理论逻辑是否自洽？
是否存在逻辑的缺口或者漏洞？后续需要写论文。
```

## 3. 理论对应到代码和大纲

```text
基于这个完善下相应的代码，并维护一个论文大纲。
```

## 4. 完善后两问并验证接口

```text
现在基于你问题1和问题2的建模，完善问题3和问题4。
优先完成官方模拟测试的接口测试。
你看下是否能自动化完成官方测试并自主迭代优化。
```

这是具有模拟器的题目的调用方式。是否演练、是否正式，以及正式次数授权按实际上下文确认，不能把这段例子当作任意正式开局许可。

## 5. 核验其他AI的review

```text
这里有一份对原始idea的review，你查看一下是否有值得完善和优化的地方。
文件在：<review文件路径>。
```

## 6. 维护完整的理论推导

```text
你额外维护一份整个数学建模的问题的数学理论推导和优化，越详细越好。
如果有权威文献证明可以对应附上，对齐所有不确定的地方并和整体论文对齐。
这次过程需要彻底解决理论问题。
```

## 后续：不断review、改进与论文微调

后续无需一次写完全部任务，沿已有项目短句推进。例如：

```text
继续。
```

```text
看下新一轮的review，是否存在这些问题？能不能再改进？
```

```text
目前先不用改动论文。
```

```text
把数据补充到论文对应表格中，做最小修改。
```

技术核验、实验选择、统计口径和实现细节由助手根据任务落实，不要求使用者把专业检查清单写进prompt。换新会话时给项目位置，让助手读取AGENTS和工作文档续接。
