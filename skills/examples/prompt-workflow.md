# 我的数模 Prompt 协作方式

本流程由一个真实建模项目的交互方式提炼而来。示例经过泛化，不公开比赛数据、身份或完整聊天记录。它描述如何与助手持续协作，不保证某种模型获奖，也不要求增加 agent 数量。

## 核心：给目标与边界，用证据推进

一次长对话可以按“读题与初始思路 → 理论审查 → 实现 → 外部review → 实验迭代 → 冻结 → 论文和代码支撑”推进，但实际可以回退或跳转。每阶段都把当前采用版本、依据和未完成事项记入文件；聊天不是唯一状态来源。

我常用的提示并不长，主要承担五个作用：

| 提示作用 | 典型说法（泛化） | 助手应采取的行动 |
|---|---|---|
| 指定材料与范围 | 根据题目和初始idea实现，先专注前两问 | 读取材料，完成范围内工作，建立模型依赖 |
| 追问论证 | 理论是否自洽？还有什么漏洞？这次彻底解决理论问题 | 提供证明、反例或修正模型，区分仍未证明的边界 |
| 调整评价 | 不强求固定提速比例，优先鲁棒性；固定一批案例再比较 | 采用可复现对照，保留尾部、失败与完整分母 |
| 纠正证据来源 | 本地模型和官方一致吗？不能保证就提高官方验证权重 | 列出一致与未知项，不能把合成结果冒充官方结果 |
| 控制阶段与动作 | 暂不改论文；先别正式启动；只做最小修改；测到这里 | 保留边界，按明确授权执行或停止相应动作 |

“继续”是省略提示：在同一上下文中沿当前目标推进，不代表取消旧限制。新会话需要项目路径和工作账本；不能假定读取过旧聊天。

## 可复用的阶段提示

**启动：把读题、实现和记录一起交给助手。**

```text
使用 $cumcm-modeling。读取题目、附件和 idea.md，实现并验证初始思路。
先维护 AGENTS.md、以题目为标题的工作文档、理论推导和论文大纲。
按我的现有身份维护本地 Git；当前只做前两问，不启动正式测试。
```

**理论：要求关闭缺口，而不是反复润色同一个解释。**

```text
审查这两问的模型是否自洽，列出实际成立的假设和最优性的确切目标。
每个疑点给证明、反例或修正；数值实验不能替代连续最坏情形证明。
把推导对应到代码入口和将来论文位置，不能仅留下待办清单。
```

**Review：让助手裁决建议，而不是照单实现。**

```text
看 review.md 是否确实指出了问题。
逐条区分成立、附条件成立、被反例否定和证据不足。
对值得采纳的内容改代码并验证，先不改论文。
```

**优化：大胆提出机制，但保留可证伪性。**

```text
继续优化后两问，不必强求固定百分比。
先固定开发集，使用同案例对照，再用独立确认和压力测试检查。
报告平均效果、尾部、最大退化和失败；本轮预算两小时。
若只有有限候选最优，就如实说明，不称理论全局最优。
```

**实际系统：从怀疑模型到增加真实验证。**

```text
核对本地环境与官方规则的一致性，列出无法确认的部分。
允许进行演练各5局，保留全部开局请求和结局；不启动正式测试。
只有退出、导出和结果核对完成后才开始下一局。
```

**冻结与交付：把调参与正式成绩分开。**

```text
冻结已验证算法，先做正式预检，等我明确授权再启动。
测试完成后仅将真实成绩最小同步到对应表格。
整理可独立运行的代码支撑材料，论文不能写未部署的候选方法。
```

## 为什么这种方式有效

提示以问题和验收结果为中心，助手有空间选择实现办法，但必须用文件与证据说明结果。人负责目标、风险偏好、阶段切换和实际观察，助手负责读资料、推导、实现、测试、记录和交付。对外部review、错误与结果差异的追问促使模型与程序相互校验。

关键不在多次重复“最优”“彻底”，而在将它们转成可检查要求：哪类策略空间、什么目标、哪些误差、什么证明、哪组实验、什么完成证据。无法证明的地方保留边界，不靠措辞封闭问题。

## 开源使用建议

- 首次提示写材料、目标、边界和交付；后续用短提示纠偏，不需要重复完整角色设定。
- 长任务设置可承受的实验预算，停止时记录当前版本；没有新证据不重复扩测。
- 模拟器是可选分支，通常数据建模题使用本地实验即可。
- 论文模板只承载真实结论：先填方法与证据，再写摘要和评价，勿让模板示例变成比赛结果。
- 将通用经验回馈技能仓库，项目参数、真实成绩和敏感日志留在各自项目中。

开箱模板见 [LaTeX 模板](../../latex-template/README.md)，更多独立场景见 [提示词库](prompt-examples.md)。
